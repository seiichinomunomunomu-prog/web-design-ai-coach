# Phase 9 Step 1：Create Mode v0.1 要件定義・確定版

## 1. 目的

Create Modeは、Web制作初心者が「作りたいWebページ」を
自然な日本語で入力すると、AIがその要望を理解し、
HTML / CSS / JavaScriptを生成する機能とする。

Create Mode v0.1では、

要望入力
↓
AIコード生成
↓
HTML / CSS / JavaScript表示
↓
コードコピー
↓
Webページプレビュー

までを一連の操作として実行できることを目標とする。


## 2. Review Modeとの役割分担

### Review Mode

入力：
- 既存HTML
- 既存CSS
- 既存JavaScript
- 質問

AIの役割：
- コードレビュー
- 問題点の確認
- 修正提案
- Focused Review / General Review

### Create Mode

入力：
- 作りたいWebページについての自然言語による要望

AIの役割：
- 新しいWebページの生成

出力：
- HTML
- CSS
- JavaScript
- 生成コードの簡単な説明
- Webページプレビュー


## 3. Mode切替

Review ModeとCreate Modeは別画面とする。

画面上部にMode切替を配置する。

[ Review Mode ] [ Create Mode ]

- Review Modeを選択するとReview専用画面へ移動する
- Create Modeを選択するとCreate専用画面へ移動する
- AIによるReview / Createの自動判定は行わない
- ユーザー自身がModeを選択する
- Review Mode v1.1の既存画面・処理への影響を最小化する


## 4. Create Mode入力

Create Mode専用画面に、
作りたいWebページの要望を入力する欄を設ける。

例：

「カフェのホームページを作ってください。
上部に店名とメニューを表示し、
中央に大きなメインビジュアル、
その下に店舗紹介とアクセス情報を表示してください。
スマートフォンにも対応してください。」

要件：

- 日本語の自然言語で要望を入力できる
- 入力した要望をAIへ送信できる
- Create Mode専用の処理へ送信する
- 初心者でも使いやすいシンプルな入力画面とする


## 5. AIコード生成

ユーザーの要望をもとに以下を生成する。

- HTML
- CSS
- JavaScript

JavaScriptは必要な場合のみ生成する。

生成方針：

- 初心者が理解しやすいコードとする
- 過度に複雑な構成を避ける
- HTML / CSS / JavaScriptを明確に分離する
- レスポンシブデザインを考慮する
- 生成コードについて簡単な説明を表示する


## 6. 生成コード表示

生成されたコードは、

- HTML
- CSS
- JavaScript

の3つに分けて表示する。

各コード欄には、

HTML                         [ コピー ]
┌─────────────────────────────┐
│                             │
│ HTMLコード                  │
│                             │
└─────────────────────────────┘

CSS                          [ コピー ]
┌─────────────────────────────┐
│                             │
│ CSSコード                   │
│                             │
└─────────────────────────────┘

JavaScript                   [ コピー ]
┌─────────────────────────────┐
│                             │
│ JavaScriptコード            │
│                             │
└─────────────────────────────┘

のように、コード種別とコピーボタンを表示する。

要件：

- HTML / CSS / JavaScriptを独立した欄に表示する
- コードの改行・インデントを保持する
- 読みやすい状態で表示する
- JavaScriptが不要な場合は空欄または「なし」とする


## 7. コードコピー機能

HTML / CSS / JavaScriptそれぞれに
個別のコピーボタンを設ける。

- コピーボタンは各コード欄の右上に配置する
- HTMLはHTMLのみコピーする
- CSSはCSSのみコピーする
- JavaScriptはJavaScriptのみコピーする
- コピー成功時は「コピーしました」など完了したことが分かる表示を行う
- コピー操作ではAIへの送信や再生成を行わない


## 8. 生成コードの編集方針

Create Mode v0.1では、
生成されたHTML / CSS / JavaScriptは
閲覧およびコピーを目的として表示する。

v0.1ではコードの直接編集機能は提供しない。

ただし、将来のバージョンで以下を追加できるよう、
拡張しやすい画面・データ構造で実装する。

- HTML / CSS / JavaScriptの直接編集
- 編集後のプレビュー更新
- AIによる生成コードの再修正
- 生成コードの再利用


## 9. プレビュー機能

AIが生成したWebページを
Create Mode画面内でプレビュー表示する。

要件：

- HTML / CSS / JavaScriptを組み合わせてプレビューする
- プレビューをWeb Design AI Coach本体から分離して表示する
- 生成されたCSSがアプリ本体へ影響しない構成とする
- 生成されたJavaScriptがアプリ本体へ影響しない構成とする
- プレビューの安全性を考慮した実装方式を採用する
- レスポンシブなWebページも確認できる構成を検討する

具体的なプレビュー実装方式と安全性については、
実装前に別途設計する。


## 10. UI

Create Modeであることが明確に分かる画面とする。

AI生成実行時：

- 「AI生成中...」など処理中であることを表示する
- 必要に応じてスピナーを表示する
- 生成中は生成ボタンを無効化する
- 二重送信を防止する
- AI生成完了後は通常状態へ戻す


## 11. Create Mode v0.1で実装しない機能

以下はv0.1の対象外とする。

- 生成コードの直接編集
- 編集後のプレビュー更新
- AIとの複数回の対話による再デザイン
- 生成履歴
- データベース保存
- ユーザー別プロジェクト管理
- ファイルダウンロード
- AI画像生成
- React / Vue等のフレームワーク生成
- サーバーサイドコード生成
- 生成したWebサイトの自動公開

これらは必要に応じてv0.2以降で検討する。


## 12. Review Modeへの影響防止

Create Mode追加によって、
現在FIXしているReview Mode v1.1を壊さないことを重要要件とする。

- Review Modeの既存Promptへの変更を最小限にする
- Review ModeとCreate Modeの処理を可能な限り分離する
- Create Mode専用Prompt / 処理を使用する
- Focused Reviewを維持する
- General Reviewを維持する
- Review Mode UI-01を維持する
- Review Mode UI-02を維持する

Create Mode実装後にReview Modeの回帰テストを行う。

# Phase 9 Step 2：Create Mode画面仕様・確定版

## 目的

Create Mode v0.1の画面構成およびユーザー操作を定義する。

Create ModeはReview Modeとは別画面とし、

要望入力
↓
AIコード生成
↓
生成コード確認・コピー
↓
Webページプレビュー
↓
コードの説明

という流れで利用できる画面とする。

Review Mode v1.1への影響を最小化し、
Create Mode専用画面として実装する。


# Step 2-1：Mode切替・URL構成

Review ModeとCreate Modeは別画面とする。

画面上部にMode切替を配置する。

[ Review Mode ] [ Create Mode ]

URL構成：

/         → Review Mode（既存）
/create   → Create Mode（新規）

要件：

- Review Modeを選択すると既存Review画面へ移動する
- Create Modeを選択するとCreate専用画面へ移動する
- 現在選択しているModeを見た目で識別できる
- Review / CreateのAIによる自動判定は行わない
- ユーザー自身がModeを選択する
- 既存Review Modeの「/」ルートを維持する
- Review Mode v1.1への変更を最小限にする


# Step 2-2：Create Mode入力エリア

Create Mode専用画面に、
作りたいWebページの要望を入力するエリアを配置する。

画面イメージ：

Create Mode

作りたいWebページの要望

┌─────────────────────────────────────┐
│                                     │
│  カフェのホームページを作って...   │
│                                     │
│                                     │
└─────────────────────────────────────┘

        [ AIでWebページを作成 ]

要件：

- 要望入力欄は複数行入力できるtextareaとする
- 日本語の自然言語で入力できる
- 初心者が入力内容をイメージしやすい例文またはplaceholderを表示する
- PCでは5～7行程度を確認できる高さを目安とする
- 入力欄の下に「AIでWebページを作成」ボタンを配置する
- 要望が空欄の場合はAI生成を実行しない
- v0.1では用途・色・機能などを個別フォームに分割しない
- 1つの大きな要望入力欄へ自由に記述する方式とする


# Step 2-3：生成コード表示エリア

AIが生成したコードを以下の3つに分けて表示する。

1. HTML
2. CSS
3. JavaScript

画面イメージ：

HTML                                  [ コピー ]
┌──────────────────────────────────────────────┐
│ <header>                                     │
│     ...                                      │
│ </header>                                    │
└──────────────────────────────────────────────┘

CSS                                   [ コピー ]
┌──────────────────────────────────────────────┐
│ body {                                       │
│     margin: 0;                               │
│ }                                            │
└──────────────────────────────────────────────┘

JavaScript                            [ コピー ]
┌──────────────────────────────────────────────┐
│ const button = ...                           │
└──────────────────────────────────────────────┘

要件：

- HTML / CSS / JavaScriptを独立した欄に表示する
- 表示順はHTML → CSS → JavaScriptとする
- 各コード欄の左上にコード種別を表示する
- 各コード欄の右上に「コピー」ボタンを配置する
- コードの改行・インデントを保持する
- コードが長くても画面レイアウトが崩れない構成とする
- コード欄は一定の高さを持たせる
- 長いコードは各コード欄の内部で縦スクロールできるようにする
- PCでは300～400px程度を実装時の目安とする
- v0.1ではコードを直接編集できない閲覧専用表示とする

コード表示は、

<pre><code>...</code></pre>

などの閲覧専用構造を第一候補とする。

ただしHTML / CSS / JavaScriptのデータ自体は独立して保持し、
将来の編集機能へ拡張しやすい構成とする。


## コードコピー

- HTML / CSS / JavaScriptをそれぞれ個別にコピーできる
- HTMLのコピーではHTMLのみをコピーする
- CSSのコピーではCSSのみをコピーする
- JavaScriptのコピーではJavaScriptのみをコピーする
- コピー成功時は一時的に「コピーしました」などの表示へ変更する
- コピー操作ではページ送信やAI再生成を行わない

JavaScriptを使用していない場合：

- 「このページではJavaScriptを使用していません。」など分かりやすく表示する
- コピーするコードが存在しない場合はコピーボタンを無効化する


# Step 2-4：プレビューエリア

生成コードの下にWebページのプレビューを表示する。

画面イメージ：

プレビュー

[ PC ] [ Smartphone ]

┌──────────────────────────────────────────────┐
│                                              │
│          生成されたWebページ                │
│                                              │
└──────────────────────────────────────────────┘

要件：

- HTML / CSS / JavaScriptを組み合わせて表示する
- Web Design AI Coach本体とは分離して表示する
- 生成CSSがアプリ本体へ影響しない構成とする
- 生成JavaScriptがアプリ本体へ影響しない構成とする
- プレビュー領域には一定の高さを持たせる
- 生成ページが領域より大きい場合はプレビュー内でスクロールできるようにする
- v0.1ではプレビュー上で直接編集しない


## PC / Smartphone切替

プレビューに以下の切替を設ける。

[ PC ] [ Smartphone ]

PC：

- 広い画面幅でプレビューする

Smartphone：

- スマートフォン相当の細い画面幅でプレビューする
- 同じ生成ページのレスポンシブ状態を確認できる

ブラウザ自体のサイズを変更しなくても、
Create Mode画面内でレスポンシブ表示を確認できる構成とする。


## プレビュー実装方針

プレビュー分離にはiframeを第一候補とする。

HTML / CSS / JavaScriptを組み合わせ、
iframe内に生成ページを表示する方式を検討する。

ただし、生成JavaScriptの実行には安全性の検討が必要なため、
iframe sandbox等の具体的な安全設計は実装前に別途決定する。


# Step 2-5：生成コードの説明エリア

プレビューの下に「コードの説明」を表示する。

例：

コードの説明

このページは、
ヘッダー、メインビジュアル、店舗紹介、
アクセス情報で構成されています。

CSSではFlexboxを使用しています。
スマートフォンでは縦並びになるようにしています。

JavaScriptはメニューボタンの開閉に使用しています。

要件：

- 初心者向けに簡潔に説明する
- 専門用語を必要以上に多用しない
- 使用した主なHTML構造を説明する
- 主なCSSレイアウトを説明する
- レスポンシブ対応について説明する
- JavaScriptを使用した場合は役割を説明する
- JavaScriptを使用していない場合は無理に説明を追加しない
- コード全文を説明文で繰り返さない
- 詳細な教材ではなく、生成コードの理解を助ける補助情報とする


## 将来の詳細解説機能

v0.1では簡潔な説明のみとする。

ただし将来、

- 「詳しく解説する」ボタン
- HTMLの詳しい解説
- CSSの詳しい解説
- JavaScriptの詳しい解説
- 初心者向け用語説明
- コードの特定部分を指定した解説

などを追加しやすい構成を考慮する。

これらの詳細解説機能自体はv0.1では実装しない。


# Step 2-6：生成前／生成中／生成後の画面状態

Create Modeの画面状態を、

1. 生成前
2. 生成中
3. 生成後
4. 生成失敗

に分ける。


## 1. 生成前

- 要望入力欄を表示する
- 「AIでWebページを作成」ボタンを表示する
- 生成コードは未生成状態とする
- プレビューは未生成状態とする
- コードの説明は未生成状態とする
- 要望が空欄の場合は生成しない

必要に応じて、

「生成後にここへHTMLコードが表示されます」
「生成後にここへプレビューが表示されます」

などの案内を表示する。


## 2. 生成中

- 生成ボタンを無効化する
- ボタン表示を「AI生成中...」へ変更する
- スピナーなどで処理中であることを表示する
- 二重送信を防止する
- 要望入力欄は表示したままとする
- 生成完了まで新しい生成操作を行えない状態とする


### 再生成時

すでに生成結果が存在する状態で再生成した場合は、
前回結果を表示したまま生成処理を行う。

前回結果
↓
「AI生成中...」
↓
生成完了
↓
新しい結果へ置換

対象：

- HTML
- CSS
- JavaScript
- プレビュー
- コードの説明

これは生成履歴機能ではない。

新しい生成結果を受信した時点で、
前回結果を最新結果へ置き換える。


## 3. 生成後

- 生成ボタンを通常状態へ戻す
- 「AIでWebページを作成」表示へ戻す
- HTMLを表示する
- CSSを表示する
- JavaScriptを表示する
- コピーボタンを利用可能にする
- プレビューを表示する
- コードの説明を表示する
- 入力した要望を保持する

ユーザーは要望を書き換え、
再度AI生成できる。


## 4. 生成失敗時

- 生成ボタンを通常状態へ戻す
- スピナーを停止する
- 二重送信防止状態を解除する
- 入力した要望を保持する
- エラーが発生したことを分かりやすく表示する
- 要望を再入力せず再実行できる状態へ戻す
- 内部エラーの詳細をそのままユーザーへ表示しない
- 初心者にも分かるエラーメッセージとする
